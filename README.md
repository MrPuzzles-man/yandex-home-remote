# Yandex Home Remote

Первая запускаемая итерация персонального пульта Яндекс Умного дома: TypeScript backend, Telegram-бот с динамическими кнопками и локальный SQLite-кеш.

Документация:

- [инструкция для обычного пользователя](docs/GUEST_GUIDE.md);
- [developer handoff: запуск, потоки и продолжение разработки](docs/DEVELOPER_HANDOFF.md);
- [архитектура и техническое устройство системы](docs/ARCHITECTURE.md).

## Что уже работает

- официальный пользовательский API `https://api.iot.yandex.net`;
- получение домов, комнат, устройств, групп и сценариев;
- локальный кеш каталога в SQLite;
- Telegram long polling без белого IP и входящих портов;
- owner-only доступ и только личные чаты;
- одноразовые callback ID с привязкой к пользователю и TTL;
- динамические кнопки для `on_off`, `toggle`, `range` и `mode`;
- запуск сценариев;
- повторная проверка устройства и возможности перед каждой командой;
- последовательное выполнение конкурирующих команд одному устройству;
- блокировка замков и security system;
- журнал команд без токенов;
- локальный Fastify health endpoint и защищённое чтение каталога;
- запуск без Home Assistant и Telegram-токена;
- отдельный адаптер Home Assistant + AlexxIT/YandexStation для громкости и запуска музыки.

Пока не реализованы: ручной ввод чисел, color picker, управление группами в интерфейсе, роли друзей, Mini App и Windows service.

## Быстрый запуск

Требуется Node.js 22 или новее.

```powershell
npm install
Copy-Item .env.example .env
```

В `.env` заполните:

- `YANDEX_IOT_TOKEN` — OAuth-токен с правами `iot:view` и `iot:control`;
- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `OWNER_TELEGRAM_ID` — числовой Telegram ID владельца.

Не отправляйте `.env` в чат и не добавляйте его в git.

### Получение Yandex OAuth-токена по Client ID и Client Secret

В настройках OAuth-приложения сначала проверьте два условия:

- приложению разрешены scopes `iot:view` и `iot:control`;
- в Redirect URI добавлен точный адрес `https://oauth.yandex.ru/verification_code`.

Затем в PowerShell, находясь в папке проекта, выполните:

```powershell
$env:YANDEX_CLIENT_ID = Read-Host 'Yandex Client ID'
$secret = Read-Host 'Yandex Client Secret' -AsSecureString
$env:YANDEX_CLIENT_SECRET = [Net.NetworkCredential]::new('', $secret).Password
npm run auth:yandex
Remove-Item Env:\YANDEX_CLIENT_ID, Env:\YANDEX_CLIENT_SECRET
```

Команда откроет страницу согласия Яндекса. После подтверждения скопируйте показанный одноразовый код обратно в терминал. Код действует 10 минут. Скрипт обменяет его на токен, проверит доступ к умному дому и сохранит `YANDEX_IOT_TOKEN` и, если он выдан, `YANDEX_IOT_REFRESH_TOKEN` в `.env`. Секрет и токены в консоль не выводятся.

Сначала проверьте доступ Яндекса без запуска бота:

```powershell
npm run probe:yandex
```

Команда выводит только каталог и возможности, но не токен. Затем:

```powershell
npm run check
npm run dev
```

Проверка локального процесса:

```powershell
Invoke-RestMethod http://127.0.0.1:3000/health
```

В Telegram используйте `/start` и `/sync`. После настройки Home Assistant доступны:

```text
/volume 3
/play We're Not Gonna Take It группы Twisted Sister
/say Ужин готов
/pause
/resume
```

Главное меню владельца `/start` состоит из трёх разделов:

- «Устройства» — выбор активной колонки и отдельный просмотр состояния всех устройств;
- «Сценарии» — «Авторские» сценарии Яндекс.Дома и «Базовые» команды Алисы;
- «Музыка и громкость» — `Play`, `Pause`, громкость `1–10`, «Включить песню» и «Произнести фразу».

Обычный авторизованный пользователь видит только «Музыка и громкость». Он может добавить песню, посмотреть очередь, установить громкость `1–6` и отправить текст для произнесения на колонке. Песня запускается автоматически, если очередь свободна, поэтому после добавления нажимать `Play` не нужно. Управление воспроизведением, переключение и очистка очереди, выбор колонки, устройства и сценарии доступны только владельцу.

После выбора колонки именно она используется музыкальным разделом. После «Включить песню» бот принимает название и исполнителя следующим сообщением.
После «Произнести фразу» следующий текст передаётся колонке как TTS, а не как команда Алисе; облачная интеграция ограничивает фразу 100 символами.
Получение речи с микрофона колонки и преобразование её в текст (STT) не реализовано: текущая интеграция YandexStation не предоставляет backend аудиопоток микрофона.
Владелец может устанавливать громкость `0–10` (`1–10` через inline-кнопки). Для остальных авторизованных пользователей доступны только уровни `1–6`; ограничение проверяется и для `/volume`, поэтому его нельзя обойти ручным вводом или старой кнопкой.

Музыкальные запросы сохраняются в SQLite-таблице `music_queue`. Воспроизведение направляется прямо выбранной колонке через Home Assistant/YandexStation; Music Assistant не управляет звуком и используется только как необязательный источник телеметрии. Кнопка «Следующий» берёт следующую запись SQLite и отправляет её выбранной колонке, а доступная только владельцу кнопка «Очистить очередь» удаляет активные записи SQLite и по возможности очищает старую очередь Music Assistant.

Строка «Сейчас играет» берётся только из фактической телеметрии, а не из SQLite. Если интеграции не возвращают название, бот честно показывает «нет данных от колонки». При `Play` уже играющий или поставленный на паузу трек продолжается; сохранённая запись SQLite запускается заново только когда колонка достоверно находится в состоянии `idle` и фактического трека нет.

Для дополнительной телеметрии в `.env` задаются `MUSIC_ASSISTANT_URL`, `MUSIC_ASSISTANT_TOKEN` и `MUSIC_ASSISTANT_PLAYER_ID`. Home Assistant в текущей конфигурации возвращает состояние и громкость, но не название, длительность или событие завершения трека. Поэтому автоматическое переключение работает консервативно: только после подтверждённого `idle`, без угадывания по таймеру и без прерывания играющего трека.

Базовые сценарии включают погоду, новости, Мою волну, любимую музыку, утреннее шоу и управление будильниками. Новый будильник создаётся через время `ЧЧ:ММ` и выбор повтора: один раз, ежедневно, по будням или по выходным. Также доступны голосовая проверка установленных будильников, включение/отключение всех и смена общей мелодии будильников выбранной колонки. Текущий адаптер озвучивает список будильников на колонке, но пока не возвращает его в Telegram как редактируемую таблицу.

Владелец видит дополнительный раздел «Управление пользователями». Новый пользователь пишет боту `/start`, после чего заявка сохраняется в SQLite. Владелец открывает «Заявки» и принимает или отклоняет её inline-кнопкой; пользователь получает уведомление о решении. Повторный `/start` не создаёт дубликат ожидающей заявки. Ручная выдача по `@username` и отзыв доступа также доступны. Выданный доступ является гостевым: добавление песен, просмотр очереди, TTS и громкость `1–6`; административные и остальные управляющие функции остаются у владельца.

## Запуск через Docker

Docker Desktop должен быть запущен. Файл `.env` остаётся только на компьютере и исключён из Docker build context.

Первый запуск или пересборка:

```powershell
npm run docker:up
```

После этого бот и Home Assistant работают в фоне. Home Assistant доступен только локально по адресу `http://127.0.0.1:8123`. Контейнеры автоматически перезапускаются после сбоя и после запуска Docker Desktop.

Music Assistant запускается в том же Docker-стеке и доступен по адресу `http://127.0.0.1:8095`. Для обнаружения колонок ему нужен host networking: в Docker Desktop должна быть включена опция `Settings → Resources → Network → Enable host networking`. Его настройки и музыкальная база хранятся в отдельном volume `home-remote-music-assistant-data`.

Управление:

```powershell
npm run docker:status  # состояние и health
npm run docker:logs    # живые логи, выход Ctrl+C не останавливает бот
npm run docker:stop    # выключить
npm run docker:start   # включить без пересборки
npm run docker:down    # удалить контейнер и сеть, но сохранить базу
```

SQLite хранится в именованном volume `home-remote-data` и переживает `stop`, `down` и пересборку образа. Не выполняйте `docker compose down -v`, если хотите сохранить локальный кеш и журнал.

Health-check доступен только на самом компьютере: `http://127.0.0.1:3000/health`. Наружу Home Assistant, Docker socket и управление компьютером не публикуются.

### Подключение Станции к боту

Интеграция YandexStation устанавливается в Home Assistant автоматически при сборке Docker-стека. После входа в аккаунт Яндекса укажите в `.env`:

- `HOME_ASSISTANT_TOKEN` — Long-Lived Access Token из профиля Home Assistant;
- `YANDEX_STATION_ENTITY_ID` — идентификатор медиаплеера, например `media_player.yandex_station_xxx`.

Затем пересоберите только приложение:

```powershell
docker compose up -d --build app
```

Команда `/volume N` принимает целое число от 0 до 10. `/play запрос` отправляет запрос Алисе через `media_player.play_media` с типом `command`.

Важно: одновременно должен работать только один экземпляр бота. Перед Docker-запуском остановите `npm run dev`, иначе два процесса будут конкурировать за Telegram long polling.

## Важная поправка к исходной концепции

Этот клиент не реализует provider API вида `/v1.0/user/devices/action`, который Яндекс вызывает у производителей устройств. Для личного пульта используется user API:

- `GET /v1.0/user/info`;
- `GET /v1.0/devices/{device_id}`;
- `POST /v1.0/devices/actions`;
- `POST /v1.0/groups/{group_id}/actions`;
- `POST /v1.0/scenarios/{scenario_id}/actions`.

## Проверка готовности этой итерации

```powershell
npm run check
```

Тесты покрывают неизвестного пользователя, чужую и устаревшую кнопку, ограничения capability, последовательность одновременных команд, корректный user API URL, безопасную обработку ошибки API и преобразование музыкальных команд в вызовы Home Assistant.

## Следующий технический шаг

Создать Long-Lived Access Token в профиле Home Assistant, записать его в `.env`, пересобрать `app` и проверить `/volume 3` и `/play ...` уже из Telegram.

Результаты проверки вариантов управления Станцией находятся в [docs/STATION_AUDIO_RESEARCH.md](docs/STATION_AUDIO_RESEARCH.md). Вывод: официальный `audio_player` не даёт достаточного публичного action-контракта; рекомендуемый адаптер — Home Assistant + AlexxIT/YandexStation, с отдельной проверкой локального режима из Docker.
