# Управление Яндекс Станцией: проверка вариантов

Дата проверки: 1 ноября 2026 года. Реальное устройство: Станция Мини 2 без часов «Пятница».

## Короткий вывод

`devices.capabilities.audio_player` из официального Yandex IoT user API не является достаточным публичным контрактом управления музыкой. В ответе реальной Станции capability имеет `retrievable: false` и не содержит списка допустимых actions. В официальном описании user API есть общая отправка действий устройству, но отдельный публичный action-контракт для `audio_player` найти не удалось.

Практически рабочий путь — Home Assistant с интеграцией [AlexxIT/YandexStation](https://github.com/AlexxIT/YandexStation), а наш backend обращается к Home Assistant REST API. Это изолирует нестабильные протоколы Станции в поддерживаемом community-адаптере.

## Что делает YandexStation 3.22.3

Проверен исходный код commit `4e8567b8dd06679d233233ebb17f9d56a9b2003a`, лицензия MIT.

Интеграция использует два канала.

### Облачный режим

- Работает для всех колонок, включая Станцию Мини 2.
- Создаёт служебный сценарий `ХА <device_id>`.
- Перед каждой командой изменяет действие сценария через закрытый Quasar API и запускает сценарий.
- `play`, `pause`, `next`, `previous` и громкость реализованы как текстовые команды Алисе: «продолжить», «пауза», «следующий трек», «громкость на N».
- `media_content_type: command` позволяет отправить «Включи ...»; это работает через интерпретацию фразы Алисой, поэтому точный трек не гарантирован.
- Облачный текст ограничивается интеграцией до 100 символов.

Это не официальный публичный API. Маршруты `/m/v4/user/scenarios/...` могут измениться без обратной совместимости.

### Локальный режим Glagol

- Станция обнаруживается через mDNS `_yandexio._tcp.local.`.
- Соединение идёт по локальному WebSocket с токеном, полученным через аккаунт Яндекса.
- Есть прямые команды `play`, `stop`, `next`, `prev`, `setVolume`, `rewind`.
- Можно проигрывать `album`, `track`, `playlist` по ID Яндекс Музыки и поддерживаемые ссылки.
- Для Станции Мини 2 платформа `yandexmini_2` явно присутствует в текущем коде интеграции.

Для локального режима Home Assistant должен видеть multicast/mDNS домашней сети. Docker Desktop на Windows может осложнить discovery: bridge-сеть хорошо подходит для облачного режима, но локальный режим нужно проверять отдельно на реальном Docker networking.

## Что подтверждает Habr

- [Статья автора интеграции](https://habr.com/en/articles/508106/) описывает локальный WebSocket-протокол, mDNS, авторизацию токеном и возможность передавать текстовые команды.
- [Консольный клиент yastation](https://habr.com/ru/articles/657657/) использует второй путь: закрытый HTTP API и автоматически создаваемые сценарии для start/stop/next/previous/volume/play by name.
- Более свежий [обзор домашнего сервера](https://habr.com/ru/articles/1033216/) также указывает, что прямого официального API Станции нет и практическая интеграция строится на AlexxIT/YandexStation.

Habr здесь является вторичным источником. Решение основано прежде всего на актуальном коде интеграции и фактическом ответе нашей Станции.

## Рекомендуемая реализация

1. Оставить официальный `api.iot.yandex.net` для обычных устройств и запуска уже существующих сценариев.
2. Поднять Home Assistant и установить YandexStation через HACS или вручную из release.
3. Авторизовать интеграцию QR-кодом — это рекомендуемый ею способ; наш OAuth-токен `iot:view/iot:control` для этого не подходит.
4. Сначала проверить облачные операции: `command`, volume, pause/resume, next/previous.
5. Затем проверить, обнаруживается ли «Пятница» локально из Docker. Только при подтверждённом local mode включать play by URL/track ID и точное состояние воспроизведения.
6. После проверки добавить в Home Remote `HomeAssistantClient` и allowlist операций. Произвольную команду Алисе не давать гостевым ролям.

## Что не следует делать

- Не отправлять угаданные actions в `devices.capabilities.audio_player` официального API.
- Не копировать приватные Quasar/Glagol протоколы в основной backend на первом этапе: это увеличивает стоимость сопровождения и риски безопасности.
- Не считать `playByQuery` точным поиском: в облачном режиме это свободная интерпретация команды Алисой.
- Не обещать play by URL до подтверждения локального режима именно в Docker на этом компьютере.
